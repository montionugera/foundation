- **A16** Units only, no ranges. A unit lives where the number is defined: on a
  primitive channel or on a struct field. Foundation maps common units to the standard
  codes that targets need.
  A unit is 1 to 32 printable ASCII characters with no space, case-sensitive, and
  stored as the text the file wrote. `spec::unit` maps each common unit, with one
  spelling (`degC`, `ohm`, `m/s2`), to its UN/CEFACT Recommendation 20 code, the one
  standard code. A unit that is not in the table is valid and has no code; a sink that
  needs a code fails for that channel only and names the unit (coordinator, #213).
  `Unit::given(text, code)` gives the unit of a channel that an import makes, from what
  the device gives, in this order: the table's unit for a Recommendation 20 code that
  the table holds, whatever the text is; the text when it reads as a unit; a common
  spelling of a whole unit that is not ASCII (`°C`, `°F`, `Ω`, `m³`, `m/s²`) in its
  ASCII form, where a first `µ` gives `u` and the rest is read by the last two steps.
  Else it gives none, and the import writes `fill` with the text and the code that the
  device gives, where an empty one counts as none, and no unit when it gives neither or
  when the sample type holds no number (IMPORT).
  Each text and each code is in the table once. `connector::browse::Facts` holds the
  code beside the text. `laptop.monitor` objected to a `fill` for each unit that is not
  ASCII ("an import of 500 points in `°C` stops 500 times"); `laptop.architect-2` ruled
  this order, 2026-10-16 15:00 UTC
  (https://github.com/synnaxlabs/foundation/issues/2705#issuecomment-6218302597).

  `laptop.architect-2`, 2026-10-16 15:04 UTC
  (https://github.com/synnaxlabs/foundation/issues/2705#issuecomment-6218371040).
